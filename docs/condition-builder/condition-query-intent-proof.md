# LibraDex Condition Query Intent Proof

## Purpose

This document is a checklist and proof log for condition-builder coverage.

The review starts from human-language "find data like this" intents, then attempts to express each intent through Abraxas' proven condition-builder semantics, then attempts the closest LibraDex fluent condition. Each row should eventually include test evidence or a specific reason the condition cannot be fully formed or cannot execute efficiently yet.

The goal is not to force one grammar over every type. The goal is to expose where signedness, precision, bit layout, string comparison policy, structured date encoding, GUID/binary layout, composite routing, projections, or custom codecs require different condition semantics.

## Review Rules

- Treat Abraxas as the reference for condition-builder semantics, not as a storage or SQLite implementation target.
- Treat LibraDex conditions as identity-group index selectors plus encoded primitive constraints.
- Do not assume numeric operators transfer safely across all numeric types.
- Treat bitmask conditions as logical .NET numeric predicates, not physical stored-byte predicates. Any future acceleration over big-endian/sortable encoded keys must translate logical masks/ranges through the relevant codec and keep a logical residual check for correctness.
- Do not infer custom codecs, custom comparers, or custom encoders. Record the required caller-supplied component.
- Prefer condition-builder expressions over direct index retrieval verbs.
- When LibraDex can form the condition but must scan, record that honestly.
- When LibraDex can form a condition but lacks a test, mark `Needs test`.
- When LibraDex cannot form a condition, write the closest partial expression and the blocker.

## Status Legend

- `Queued`: intent captured, not yet mapped.
- `Mapped`: Abraxas and LibraDex condition forms proposed.
- `Tested Pass`: focused test exists and passes.
- `Tested Fail`: focused test exists and fails; failure recorded.
- `Blocked`: condition cannot be fully formed or cannot execute with current primitives.
- `Policy`: condition depends on a design decision rather than mechanics.
